# Compact handoff engineering pilot — 2026-10-29

## Decision

The compact briefing improves presentation and exposes a late correction that the previous
preview omitted. **This pilot establishes neither a continuation-correctness advantage nor
a cost advantage.** Every arm, including request + repository, passed all three tasks.
V2 used fewer prompt characters and total input tokens, but more non-cached tokens and tool
calls. Keep it experimental and improve the evaluation before making performance claims.

## Method

- Codex CLI **0.153.4**, model **gpt-5.6-sol**, reasoning effort **low**.
- **12 fresh successor sessions**, three cases × four arms, one trial per cell.
- Three-minute timeout per session, no launcher reruns; all sessions exited successfully.
- Synthetic predecessor histories, not a real Claude capture or cross-provider experiment.
- Cases: a repository-sufficient clamp; unique IDs with a long message and late correction;
  port parsing with an earlier failure, later edit, and unverified assistant success claim.
- Identical initial implementation/public-test files per case, shared authorized history for
  the history-bearing arms, rotated execution order, and acceptance grading after all models stop.
- Request-only intentionally lacks later history and is an information-access control.
- All recorded evidence files passed the post-run integrity check.

V2 versus V1: **11.54% fewer supplied characters**, **5.50% fewer input tokens**, **5.74%
less wall time**, **52.70% more non-cached input + output**, and **13.33% more tool calls**.
These are sample totals, not confidence-bounded effects or subscription/dollar savings.

Non-cached usage is `input − cached input + output`. V1 received 188,160 cached input tokens
and V2 received 154,880. The arithmetic explains why fewer total input tokens can coexist with
more non-cached tokens; the experiment does not establish what caused the cache difference.
Reasoning-output counters are retained separately and are not added to output twice.

## Trace observations

1. The long-message correction is present inline in V2 and absent inline in V1. Both retain
   the same complete source record. This demonstrates selection behavior, not better outcomes.
2. The V2 successor still queried the complete submitted-message history in that case. Inline
   excerpts therefore did not eliminate full-source retrieval in the observed run.
3. V2's failure-then-edit successor made nine tool calls versus V1's four. Its first chained
   command stopped when an instructions-file search returned no matches, followed by additional
   inspection. This is observed variance, not proof that briefing wording caused the extra work.
4. That V2 run also searched a parent directory for instructions. No answer/history leakage
   was observed, but this was not an adversarial filesystem read-isolation experiment.
5. The simple repository-only arm succeeded everywhere. The tasks are too easy to discriminate
   useful task memory from ordinary repository inspection on correctness.

## Limits and next experiment

There was no real predecessor, agent-generated `HANDOFF.md`, Orca runtime comparison, repeated
trial, blinded clarification grading, or measured human effort. Capture overhead is unknown,
not zero. Wall time and cache reuse vary. Time to first useful action was not measured.

Before another budgeted run:

- Use multi-file interruptions whose changed requirements and rejected approaches cannot be
  reconstructed from the original request or public tests, alongside repository-sufficient controls.
- Verify native capture on an actual Claude task and freeze its repository and source evidence.
- Compare V1, V2, a strong handoff file, and actual Orca focused context using the same history.
- Balance cache/order effects with repeated paired trials and report cached/non-cached usage separately.
- Test targeted source windows or compact evidence lookup as a separate candidate, since full
  history queries remained common even when the relevant excerpt was already inline.

The approved 12-session budget is exhausted. Further offline analysis can use the reviewed
export; reprocessing provider traces requires a retained private archive. A new live experiment
needs a separate budget.
