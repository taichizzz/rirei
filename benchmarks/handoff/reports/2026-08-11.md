# Rirei handoff benchmark: 2026-08-11

## Verdict

The current Rirei handoff did **not** reduce total non-cached Codex tokens in this five-task
paired benchmark.

- Strong baseline: 117,146 non-cached tokens
- Rirei handoff: 132,270 non-cached tokens
- Rirei delta: +15,124 tokens (+12.9%)
- Strong baseline wall time: 394,708 ms
- Rirei wall time: 373,642 ms
- Rirei wall-time delta: -21,066 ms (-5.3%)
- Correct completions: 4/5 for both conditions
- Tasks meeting the predeclared 20% token-or-time threshold: 2/5
- Predeclared decision rule: failed

Non-cached tokens are calculated only from Codex-emitted JSONL as
`input_tokens - cached_input_tokens + output_tokens`. No missing provider metric is inferred.

remaining correct. Event reconciliation completed 32.4% faster but used 41.4% more tokens.
The remaining results were neutral or worse for tokens.

## What The Run Exposed

1. The handoff text was too large. It used 1,462-2,349 characters (366-588 estimated prompt
   tokens), while baseline prompts used 659-744 characters.
2. A one-line task request appeared both as the handoff title and Goal, duplicating expensive
   text before the agent did any work.
3. The outbound instruction used a generic `relay note <type>` placeholder. Several Codex runs
   guessed unsupported types such as `implementation`, `progress`, or `completed`, causing
   failed tool calls and additional token use.
4. `.relay/` was not ignored in the fixture repositories. Every baseline saw it in
   `git status`, and at least one baseline explicitly opened Relay files and could read the
   same notes. This contaminated the intended no-handoff control and makes the comparison
   conservative rather than clean.
5. Antigravity ignored its process working directory on one task and worked in its private
   scratch directory. That task truthfully contained no notes and is reported as a capture
   failure, not repaired data.
6. Both Retry-After conditions failed the same hidden assertion after implementing stricter
   weekday/date validation than the reference expected. The failure was not caused by the
   handoff, but the hidden edge is ambiguous enough that it should be replaced in a rerun.

## Interpretation

This run is evidence against the current claim that Rirei provides maximum value with minimum
tokens. It does not show that structured handoffs can never save tokens: one task produced a
clear token reduction and another produced a large time reduction. It shows that the current
renderer and recording instruction add too much overhead and that the experiment needs a clean
control before making a product claim.

The data supports continuing only with a narrower target:

> Send the smallest delta that Git cannot provide: next action, blocker, rejected approach,
> and one decision with rationale.

## Required Changes Before Benchmark V2

1. Do not render the original request twice. Use one bounded Goal line and a short title.
2. Remove note-recording instructions from the successor handoff. Capture notes through the
   harness lifecycle or provider-specific integration instead of spending successor tokens.
3. Omit completed-work notes by default when Git already demonstrates the work.
4. Target 200-300 handoff tokens, with a hard measured budget rather than a 1,000-token ceiling.
5. Make `relay init` locally exclude `.relay/` so it cannot appear in Git status or contaminate
   the baseline.
6. Rerun with fresh condition repositories where the baseline cannot read Relay state.
7. Replace the ambiguous Retry-After hidden assertion and retain hidden-test review before any
   provider calls.
8. Expand beyond five synthetic tasks only after the clean pilot beats the strong baseline.

## Provenance And Limitations

- Actual model calls: 15 (5 Antigravity predecessors, 10 Codex successors)
- Additional Codex process invocations rejected before model contact: 6; excluded from all
  model-call and token counts
- Codex model: `gpt-5.6-sol`, low reasoning, ephemeral sessions
- Antigravity model: `gemini-3.6-flash-low`
- The tasks are synthetic, fixed, small, and not statistically representative.
- Condition order alternated by task, but provider and machine variance remain.
- Raw logs, generated repositories, full `result.json`, and `analysis.json` remain under the
  local disposable run root `handoff-benchmark-vKjPbD` in the approved OpenCode temp directory.

This report makes no statistical-significance claim and does not claim that a failed treatment
was caused by its handoff.
